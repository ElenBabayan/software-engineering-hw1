# Nuts Subscriber Application

This application is built using a 3-layer architecture and demonstrates a subscriber to a Nuts service. The application processes incoming messages and persists them to a PostgreSQL database.

## Architecture Overview

1. **API Layer**
    - Responsible for subscribing to the Nuts service.
    - Uses a scheduled task (every 5 seconds) to simulate receiving messages.
    - Forwards messages to the Service layer.

2. **Service (Business) Layer**
    - Validates and processes messages.
    - Constructs a message entity and passes it to the Data layer.

3. **Data Layer**
    - Uses Spring Data JPA to interact with PostgreSQL.
    - Persists messages in a table (`messages`) with fields for content and timestamp.

## Prerequisites

- Java 17 (or higher)
- Maven
- Docker & Docker Compose (optional but recommended)

## Running the Application Locally

### Without Docker

1. **PostgreSQL Setup**
    - Install PostgreSQL and create a database named `nutsdb`.
    - Configure the username/password as `postgres/postgres` or adjust in `src/main/resources/application.properties`.

2. **Run the Application**
    - Build the project:
      ```bash
      mvn clean package
      ```

### With Docker Compose

1. **Build and Run Containers**
    - From the project root, run:
      ```bash
      docker-compose up --build
      ```
    - This command starts the PostgreSQL database and the application container. The app connects to PostgreSQL using the internal service name defined in the Compose file.

## PostgreSQL Schema Setup

The schema is auto‑generated by Hibernate (using `spring.jpa.hibernate.ddl-auto=update`).
